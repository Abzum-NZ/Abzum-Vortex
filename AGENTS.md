# Vortex agent instructions

Read [agent coordination](docs/build-plan/agent-coordination.md) (policy) and [fleet operations](docs/build-plan/agent-fleet.md) (procedure) before planning, dispatching, implementing or reviewing. They describe the current Codex Desktop workflow. The latest direct instruction from the owner overrides them; old runbooks, checkpoints and issue comments do not.

## Non-negotiables for every agent

- **Control plane and roles:** Codex Desktop is the control plane. The GPT-6 Sol lead at High owns coordination, every Project-field write and all merges. Native GPT-6 Luna subagents use Extra High for implementation, self-review and corrections; use Luna Extra High for bounded read-only inventory only when delegation saves work. A fresh independent GPT-6 Sol uses High for ordinary review and Extra High for privilege, authentication, SQL ownership, tenant boundaries, transactions, architecture or unresolved cross-layer failures. Sol at High or Extra High handles planning; Sol at High handles monitoring when needed. GPT-6 Astra at High is exceptional design consultation only. Record actual model and effort, not just the requested role.
- **Capacity and worktree:** the observed session capacity is four native agents total: the lead plus up to three children. Verify actual capacity and do not treat it as a target or an always-on fleet. The lead assigns and verifies an isolated managed worktree before a child edits. One issue has one editor at a time. Prioritize actionable review and fully gated merge packets; external waits must not starve qualified, independent implementation leaves. The implementer supplies a complete self-review packet before independent review. Workers never write Project fields or merge.
- **No secondary fleet:** no new Orca dispatch, headless Codex CLI fleet, custom app-server or external-model dispatch. Retired fleet artifacts are historical evidence; preserve unique work and use native Desktop sessions for new work.
- **Never push to main.** Every change reaches main through a protected pull request. Main is protected, including for administrators. Create branches with `--no-track` and push with an explicit refspec such as `git push origin HEAD:refs/heads/<branch>`.
- **Verify before merge** exactly as [agent coordination](docs/build-plan/agent-coordination.md#verification-before-merge) says, including the scoped requirements for TypeScript, web build, database replay, definitions, local preview and affected UI browser smoke. Verification is not a test: no agent creates, edits or runs tests. No hosted verification or deployment.
- **English only** in code, comments, strings, commits, PRs, issue comments, board fields and documents. Rewrite any non-English text before committing.
- **Database functions:** every migration that creates or changes a database function carries its complete canonical `create or replace function` body, identical to `supabase/schemas/<schema>/<function>.sql` (including comment and grants), changed in the same commit. A signature change is an explicit drop then create. Never read stored definitions with `pg_get_functiondef`, `prosrc` or `routine_definition`, and never patch one with `replace()`. `pnpm boundaries` enforces this ([supabase/schemas/README.md](supabase/schemas/README.md)). Migration numbers come from the lead and sort after every migration on `origin/main`.
- **Product integrity:** preserve tenant isolation, permissions, transactions, revisions, safe errors, and explicit publication and installation. Fix obsolete contracts at their root; this is a new application with no legacy compatibility. Never put business application names or special cases into generic engines. Never expose credentials. Preserve unique work before cleanup; do not blindly revert dependent migrations or later work.
- **Respect real controls and shared limits.** Report a tool-approval or repository-protection rejection with its exact cause; never retry unchanged or route around it. Provider capacity or rate limits are not denials: retry the same session a few times about 20 seconds apart before reassignment. Cache shared API evidence, respect live budgets and reset headers, reserve 20% of the hourly GraphQL budget for transitions, and fail closed on unknown or partial results.
- **Direct owner requests:** answer every direct question or request with the result, checks performed, verified changes, pending items and any precise owner action. A quiet heartbeat never suppresses a direct reply.
- **No hosted work:** no Kestra runs, Testing or Production deployment, or hosted verification. Keep preview and browser verification local and tie the evidence to the exact commit.
