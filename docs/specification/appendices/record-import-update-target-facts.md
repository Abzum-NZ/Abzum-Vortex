# Permanent-ID import update-target facts

`createRecordImportUpdateTargetFactsService` produces a bounded, server-only observation for rows that name permanent Record identifiers. It is one input to the later protected import-preview composer. It does not read import files, normalize submitted Record values, create a preview, or authorize execution.

The service accepts a verified identity session, an Application selection, and a closed data object containing a permanent Record type candidate, mapped field ID candidates, and target rows. A batch contains 1–50 targets and 1–500 distinct mapped field IDs. Each row has one positive safe-integer `rowNumber`, unique within that batch, and one `recordIdCandidate` string no longer than 256 UTF-8 bytes. Repeated target IDs remain separate rows. UUID identity is canonical PostgreSQL UUID equality; nil identifiers are refused.

The fixed `vortex_record.read_import_update_targets` database entry derives organization, Application, identity, account, access version, correlation, and expiry from the current validated human request. It resolves the current active installation and one exact published Record definition through the private Record metadata resolver. The result includes the complete active Module binding evidence, including every binding revision, and the target Module and storage identities. It does not contain an installation ID, private metadata declaration, physical token, table or column name, account session, or credential. Preview-installation and system-projection metadata are refused.

For every syntactically valid target ID, the protected function pairs `read_record` with `read_record_capabilities` under the same request. A target is matched only when it is currently readable, updateable, and every mapped field is both present in the readable projection and changeable. The matched row carries its current concurrency number and readable values. Null values and omitted fields remain unchanged. Existing values are a readable projection, never a complete stored row. Mapped generated fields of type `reference_number`, `calculation`, or `total` are refused.

An invalid target ID returns `invalid_record_id` without a lookup. Missing, foreign, unreadable, non-updateable, unreadable-field, unchangeable-field, or unsupported-storage targets share `target_unavailable`. Refused rows contain only the source row number and closed code. Invalid batch or mapping input, malformed metadata or result, changed context, installation, definition, projection, revision or mapped capability, overflow, or a failed transaction discards the whole result.

The published definition is bounded to 500 fields and 256 KiB of UTF-8 JSON. A readable value projection is bounded to 64 KiB per target, and the complete response is bounded to 5 MiB. The result expires at the earlier of the validated request expiry or 30 seconds after issue. SQL checks the live database clock before returning; the runtime checks its clock after the request transaction commits.

The immutable plain-data result has `kind: "partial_update_target_facts"` and `validationComplete: false`. It includes no `uniqueChecks` or `resolvedPendingChecks`, so it cannot satisfy `RecordImportRowResolverFacts` or complete #731. It adds no create authority, unique-match facts, Business value normalization, comparison keys, pending-check confirmations, preview composer, execution permission, HTTP route, or UI. Preview and execution remain separate; #732 must recheck current authority and source/release pins and use the ordinary Record writer with its command identity and expected concurrency number.

The database function is owned by `vortex_record_adapter`, has an empty search path, and is executable only by `vortex_request`. Its canonical schema file and installing migration contain the same complete function, owner, comment, and grants. It calls only existing protected readers and does not invoke a Record writer, receipt, Activity, Event, reference allocator, job, or Record write lock.
